## 3. Cause of the single failure

The OLD-image replay process `g2l_49` (`PG17_PROCESS … "old":true, action complete, terminal_status success`) returned `failure {status: 500, message: "Internal server error", code: "P2002"}` with 3 logged queries (`jest.log` L715), so `replay.result` was `undefined`.

What the database did: the accepted-base OLD writer `complete()` (`git show 93389265:src/scout/scout.service.ts` L262-300) runs a batch `$transaction([scoutIngestCompletion.create, scoutImport.upsert])`; the create hit the completion ledger's unique constraint (P2002) and the batch rolled back before the upsert (3 queries ≈ BEGIN, INSERT, ROLLBACK versus 4 for the successful first call). That is the designed idempotency mechanism; the row's non-change was not asserted (L987 unreached) but nothing after the rollback wrote.

Why the process reported 500 rather than the ack: the OLD writer's catch is `if (err instanceof PrismaClientKnownRequestError && err.code === 'P2002') firstTime = false; else throw err;` with `PrismaClientKnownRequestError` imported from `'@prisma/client/runtime/library'` (OLD `scout.service.ts` L4). In the OLD-image worker the two sides of that `instanceof` come from two different module instances:
- The error is thrown by the OLD client generated to a custom output (`G2_S7L_OLD_CLIENT` = `<old-root>/.g2-s7l-old-client`), whose `index.js` L30 does `require('./runtime/library.js')` — its own copied runtime (`.g2-s7l-old-client/runtime/library.js`; bootstrap comment `g2-s7l-bootstrap.sh` L199-201 documents that a custom-output client receives a runtime copy).
- The service's class comes from `@prisma/client/runtime/library`, resolved through the old-root `node_modules` symlink to `<worktree>/node_modules/@prisma/client/runtime/library.js` (bootstrap L153).
- The worker's resolve hook redirects only the bare specifier `'@prisma/client'` to `input.client/index.js` (`test/utils/g2-s7l-worker.cjs` L18-23; same as the accepted `g2-tq0-worker.cjs` L9-13); the deep specifier is not redirected.

Same bytes (bootstrap verifies the runtime sha), different module identity → `instanceof` false → the P2002 is rethrown → the worker's catch emulates Nest's 500 boundary. In the candidate image the default-output client (`node_modules/.prisma/client/index.js` L30) requires `@prisma/client/runtime/library.js` from the same package as the service import, so identity holds — consistent with L09 "a duplicate is a no-op ack" passing through the candidate's identical catch in this very run. The accepted S8-B P05 OLD-image replay (`rls-g2-s8b.spec.ts` L359-375) converges by upsert without exceptions and, where the reconstruct writer catches P2002, it uses `Prisma.PrismaClientKnownRequestError` from the bare `@prisma/client` import (redirected), so this two-runtime identity split was never exercised by an accepted proof before.

Classification: **proof-tool defect** in the OLD-image worker setup, not a product defect. In production both the service and the client load one `@prisma/client/runtime/library.js` from one `node_modules`; the OLD writer's replay-as-ack semantics on the S7-L schema are therefore **unverified** by this run, not contradicted. The spec's expectation at L986 is the correct decision statement and should not change.
