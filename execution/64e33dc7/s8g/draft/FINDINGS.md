## C5 — N3 `import_intent_id` fill: stays OUT of S8-G's seam (answers the parent's 16:42Z FYI; S9 F2 reference)
- Class: attribution truthfulness for S9's per-run `created_native` vs `already_present_verified` split (S9 READINESS F2, class A for S9 only). For S8-G: C — the verdict (`arbitrate`, `arbiter.ts` L71-88) does not read provenance, and no S8-G acceptance case depends on the column.
- Concrete harm if S8-G filled it from its owned paths: the only S8-G-owned write point is the engine's per-row transaction after `family.persist` returns (`scout-reconstruct.service.ts` L218-248). `PersistOutcome` is `ok:true` for both a row created now (`persistProgram` L122, `persistWorkoutTemplate` L353) and a row verified `already_present` (`verifyTarget` L83-88, `persistEvidence` L380-384), and carries no provenance id. An engine-level `UPDATE "ImportNativeProvenance" SET import_intent_id = $run WHERE <identity> AND import_intent_id IS NULL` would therefore stamp rows an **earlier** intent created with the current run's UUID on replay — mis-attribution in the opposite direction of F2, and irreversible without a second attribution source. Child provenance rows (`workouts.exercise`, `native-contract.ts` L40) have a different `entity_type` and would need their own predicate. Filling truthfully requires the writer to know `created` at insert time: that is `recordCreated`/`promoteToCreated`/`recordUnresolved` (`native-provenance.ts` L53-113) called from `native-writers.ts` — S8-C-owned bytes — plus a run context on `persist` (`families.ts` L52), which READINESS N3 explicitly keeps S8-G from extending.
- Second harm: `import_intent_id` is an FK to `ImportIntent(id, coach_id)` with `onDelete: Restrict` (`schema.prisma` L6978-6979). Filling it makes every intent with attributed provenance undeletable while the native rows' provenance exists — a retention/erasure semantics change of the L8 class (owner-reserved in the S7-L decision §8), not a T4 build choice.
- Exact decision blocked: none for S8-G. For S9: bucket attribution (F2), already recorded there with interim (b).
- Minimum closure (not S8-G): a small post-landing slice "N3-FILL" owned by the native writer paths — add `readonly intentUuid: string | null` to a `PersistContext` on `persist` (or to `ProvenanceKey`), set `import_intent_id` **only** in `recordCreated`/`promoteToCreated`/`recordUnresolved` insert branches (never in the `already_present` verify path), pass it from the engine's `RunContext` (server runs: `intentId` is the UUID text, `ScoutImport.intent_id = import_intent_id::text` by invariant 2; legacy runs: null). Owner decision on the Restrict FK consequence precedes it. S8-G's `RunContext` is shaped so this is additive (DESIGN §1.2, §6 N3).
- Execution unlocked now: S8-G proceeds with `import_intent_id` null (P01 asserts null explicitly so the fact is pinned); S9 v1 uses its interim (b) null split; N3-FILL is scheduled after S8-G lands, or folded into S9-B if the owner accepts the FK consequence.
