# S8-G acceptance test design (draft; evidence only)

Companion to `DESIGN.md`. Every G-case maps to (a) a unit test against doubles and (b) a real-PG case in one new proof spec. No accepted suite is re-run as part of S8-G acceptance; the S8-G proof is the single new real-PG proof for the new bytes (READINESS). Drafts of the sources live next to this file as `.draft` files (see PATHS.md for their target paths).

## 1. Harness and fixtures

### 1.1 Real PG lane (`test/rls-g2-s8g.spec.ts`, `test/utils/g2-s8g-*`)

- Cluster/database: the S7-L pattern (`test/utils/g2-s7l-db.ts`, `g2-s7l-pg-harness.ts`) with `G2_S8G_*` env names and its own disposable database `g2_s8g_disposable`. Migrations: the full accepted history at `93389265` **plus** S7-L's `20270123000000_scout_run_lifecycle_expand` (`prisma migrate deploy` from the S8-G worktree, which after landing carries both candidates). S8-C ships no migration (S8-B's provenance table is in `93389265`).
- Roles: `postgres` (owner, DDL), `service_role` (runtime), `anon`/`authenticated` (RLS denial), cluster superuser for `pg_stat_activity` only — unchanged from S7-L.
- Worker: `test/utils/g2-s8g-worker.cjs` (draft attached) = union of the S7-L worker (real `ScoutService`/`ScoutLifecycleService`, query log, `-- tx:begin|commit|rollback` markers, `before-gate`/`gated`/`locked` barriers) and the S8-C worker (head attestation, fixture spec/rules injection into `service.families`). It constructs `ScoutLifecycleService(prisma, analytics, reconstruct)` so the hook runs the real pass. New barriers: `before-lock` (before the tail's `FOR NO KEY UPDATE`), `after-row:<n>` (after the n-th row transaction commit), `before-ledger` (S8-C's, inside a row transaction after persist).
- Actions: `start | ingest | complete | cancel | status | reconstruct | run-pass` (`run-pass` calls `reconstructRun` directly with a supplied epoch, for G02/G10 without the HTTP-shaped path).
- Fixture source spec (injected, parsed by the real `parseSourceMappingSpec`): platform `conformance_s8g` with steps `{clients→clients, programs→programs, workouts→workouts, client_history→client_history}` (identity, matching the committed staging convention) and native rules for `programs` and `workouts` (the S8-C proof's rule set). `notes` is not a step → `unresolved_family:notes`. Staged rows are inserted through the real `ScoutIngestService.ingest` (server run → gated, as in S7-L L08/L09) with `sourcePlatform: 'conformance_s8g'`; payloads are synthetic (no PII).
- Statement capture: the worker's Prisma `$on('query')` log (query text only, never parameters) plus the `$transaction` proxy markers. Predicates used by assertions: `isGate = q.includes('UPDATE "ScoutImport"') && q.includes('last_observed_at')`, `isLock = q.includes('FOR NO KEY UPDATE')`, `isTerminal = q.includes('terminal_status = ')`, `isNative = /INSERT INTO "(WorkoutProgram|WorkoutPlan|WorkoutPlanExercise|ScoutReconstructedEntity)"/`, `isProvenance = q.includes('"ImportNativeProvenance"')`, `isLedger = q.includes('"ScoutReconstructionLedger"')`.
- Transaction segmentation helper: split the log at `-- tx:begin`; each segment's first SQL line (skipping Prisma's own `BEGIN`/`SET TRANSACTION`/`DEALLOCATE` lines if present) is the "first statement".
- Side-effect spies (G12): `notifications.pushToUser`, and module-level guards that `require`-hook any of `notifications`, `drip`, `assignment`, `email`, `billing` module paths from the S8-G worker and count loads/calls (the S8-C static guarantee — `native-writers.ts` L26-29 imports nothing beyond Prisma/provenance — is re-asserted dynamically).

### 1.2 Unit doubles

- Engine: the S8-C `FakePrisma` pattern (`test/scout/reconstruct/native/engine-handoff.spec.ts` L28-70: in-memory staged rows, ledger map, `txLog` of model.method calls inside `$transaction`) extended with a `$queryRaw` double that records `'gate'` into the txLog and returns the configured epoch rows, and with `scoutIngestEntity.groupBy`.
- Hook: the S7-L lifecycle doubles pattern (`test/scout/lifecycle/lifecycle.service.spec.ts` L19-67) plus a `reconstruct` double whose `reconstructRun` is a `jest.fn()` recording call order relative to `queryRaw` (`FOR NO KEY UPDATE`) and `executeRaw` (terminal UPDATE).
- Planner: pure, no doubles.

## 3. Gate script expectations (for the future builder; not executed here)

- Scoped pinned prettier/eslint on the owned paths only; Jest on the three unit drafts plus S8-C/S7-L unit suites once (composition sanity, not acceptance).
- `git diff --stat` between the landed integration head and the S8-G head must list only PATHS.md paths.
- Real PG: one `timeout -k 30 3900 bash s8g/binding/v1/<driver>.sh` on the canonical lock; the proof spec runs P01-P14 in one Jest process; terminal receipt.
