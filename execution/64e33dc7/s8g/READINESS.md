## Minimum internal seam (no new route, flag, schema, reason code or contract change)
1. **Run-aware engine entry.** An internal `reconstructRun(coachId, intentId, ctx)` next to today's `reconstruct()`. For `ctx.mode='server'` it accepts an open run in phase `reconciling` (claim committed, `fenced_at` null, terminal null) instead of `assertSettled`; for legacy rows and the coach-JWT route behaviour is byte-identical (settled gate, no epoch). The coach-JWT route on a server run in `reconciling` keeps the existing 409 (still "not settled"); readers keep their 404 until the arbiter writes the terminal.
2. **Gate first in every per-row transaction.** The S7-L `assertRunOpen(tx, coach, intent)` UPDATE is the first statement of the native/evidence transaction (before `persist`) and of `writeOutcome`. Its returned epoch is carried into the per-row CAS; the row lock is held to commit. Zero rows → the pass stops at that row, writes nothing further, and hands over to the arbiter path. Legacy path: no gate, unchanged.
3. **Family orchestration.** Enumerate distinct staged `(source_platform, entity_type)` for the intent, map each token via `resolveStep`, run canonical families in §3.8 order (`clients → programs → workouts → client_history` evidence), unmapped tokens ledgered `skipped` with `unresolved_family:<token>` and collected as `unmapped_families`. A family-level 409 (over ceiling, provenance conflict) is isolated: it stops that family, not the arbiter.
4. **Arbiter handoff, never a terminal write.** Build `{fence: null|observed, claim, staged_by_family, ledger_by_family, unmapped_families, reconciliation: null}` and call S7-L's CAS terminal writer with the epoch seen at hook entry. A CAS miss (fence raised meanwhile) is a no-op. S8-G never writes `terminal_status`, `completed_at` or `reason_code` directly and never emits `complete`.

- G03 Cancel between rows (barriers): rows before cancel have native + provenance + ledger; no row after; terminal `cancelled/cancelled_by_coach`; S8-G's arbitrate CAS misses and writes nothing; exactly one terminal write.
- G04 Cancel racing an in-flight row: the fence's `FOR NO KEY UPDATE` waits for that row's commit, no 40P01; the committed row keeps provenance and is counted; terminal still `cancelled`.
- G05 Deadline passes mid-pass: next gate returns zero rows → `timed_out/deadline_exceeded` per §3.1 in its own short transaction, acquired only after the writer's rollback (no self-wait); the pass stops; no further native rows.
- G06 Claim vs truth: claim `success` with every row reconstructed → `partial`; claim `failed` with zero staged → `failed/transfer_failed`; claim `failed` with staged rows → pass runs → `partial`.
- G07 Duplicate `/complete` while reconciling and late `/complete` after terminal: one pass only, no second hook fire, late call is 200 no-op; `/complete` refused by the gate stores nothing and starts nothing.
- G08 Legacy byte-identity: legacy intent `/complete`, coach-JWT reconstruct on legacy terminal rows and all existing `scout.service.spec.ts` / reconstruct specs unchanged.
- G09 Reader/settled gates during `reconciling`: entities/roster readers return the uniform 404; coach-JWT reconstruct returns the existing 409; after the terminal both work over the same ledger.
- G10 Unmapped token (`notes`) → ledger `skipped` `unresolved_family:notes`, in `unmapped_families`, per-intent tally holds; run at most `partial`. Over-ceiling family → no writes for that family, other families proceed, terminal still written.
- G11 Tenant isolation: coach B's staged rows and runs never enumerated; RLS anon/authenticated denial; service-role transaction rollback leaves no partial native/ledger row.
- G12 Zero side effects from the pass: notifications, drip, assignment, email, billing spies record zero calls across pass and replay.
- G13 Interrupted pass (aborted process mid-run): run stays open `reconciling`; next status poll past deadline → `timed_out`; committed rows keep provenance; a new intent's pass converges `already_present` with zero duplicates.
- G14 CAS/epoch: a fence raised after hook entry but before arbitrate → S8-G's terminal attempt is a no-op; `execution_epoch` strictly increased once; `completed_at` set exactly once.
