S8-F native readers report typed entity targets and the roster bridge qualifier

The entities read bridge dispatches on the ledger's nullable target_kind.
NULL and scout_entity rows keep the generic evidence join unchanged and are
reported with the effective kind scout_entity and a null native_id. Rows
typed workout_plan or workout_program resolve to the caller's own live
native row, and only when a same-coach import provenance record with a
created or already_present outcome vouches for that exact kind and id.
Unknown kinds, missing or archived rows, other tenants' rows and missing or
mismatched provenance are dropped (fail closed) while the ledger-anchored
cursor keeps advancing. The row DTO gains exactly two additive fields,
target_kind and nullable native_id; no payload or personal data is added.

The roster read materializes only NULL and person kind rows with the
existing Person semantics and carries roster_bridge_pending true on every
page, including empty ones, marking the interim Person bridge. It creates
no native principal and decides no S8-D or S8-E policy.

Focused default tests cover F01 to F11 (F03 runs against the programs
family that S8-C added). A disposable PG17 lane (port guard, bootstrap,
harness, live spec) is prepared for the separate real RLS proof; it is not
run here. docs/contracts/importer-openapi.json is regenerated by the
unchanged generator and the frozen contract spec pins the two new
ReconstructedEntityDto properties. Non-production branch.
