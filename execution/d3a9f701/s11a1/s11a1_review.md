# S11-A1 independent source review

**Verdict: NO-GO (proof defects; no product-code finding).** Source-only review of the eight untracked test/harness files against the accepted S11-0 record. No tests, database, package commands, or workspace modifications were run. Parent-accepted worker-action and harness deviations are not objections.

## Blocking findings

1. **B — Refused-port guard is non-discriminating.** `test/utils/g2-s11-db-guard.spec.ts:25–45,87–89` passes `ack = g2_s11_disposable:55648` to *every* mutated URL, including 55646, 55647, and 55649. Removing the explicit refused-port set from `g2S11TestTarget` would leave these cases green: the independent confirmation mismatch alone rejects them. **Harm:** regression that permits a prior lane when the operator confirms its port would escape this guard, endangering lane isolation/destructive fixture operations. **Blocked:** accepting the guard as proof of the S11-only port refusal. **Minimum fix:** add a separate negative test for each prohibited prior port with the *matching* `g2_s11_disposable:<prohibited-port>` confirmation; retain the current mismatch tests as confirmation tests. This unblocks discriminating lane-isolation proof. Production guard itself does explicitly refuse 55646/55647 (`g2-s11-db.ts:56–77`).

2. **B — J07 does not snapshot all A-owned rows despite its exact-row claim.** `test/scout/s11/journey-core.pg.spec.ts:522–569` compares A's run, setup, pairing codes, staged **count**, and A-keyed mirror, but neither staged row contents nor A's native/provenance/ledger/evidence rows or completion rows. `g2-s11-harness.ts:240–258` already exposes `targetSnapshot(coach,intent)` for the native/evidence classes. A cross-coach operation that changes A's staged payload while preserving count, or writes A-native rows, could pass this test. **Harm:** tenant-boundary corruption would be certified as “A's run and rows exactly unchanged.” **Blocked:** the J07 record's exact per-coach no-foreign-write assertion. **Minimum fix:** snapshot and compare A's staged rows (not just count), `targetSnapshot(COACH,a)`, and A completion rows before and after B's calls; assert B's own rows are isolated too where applicable. This unblocks the full row-level isolation claim.

3. **B — J08's messaging/email/drip “spies” are module-load counters, not outbound-call spies.** `test/utils/g2-s11-worker.cjs:55–104` counts matching `require` calls and resets counts to zero *after* the whole service import graph loads; `journey-core.pg.spec.ts:600–615` asserts those counters and a static `pushToUser` pattern in `scout.service.ts`. An outbound messaging/email call through an eagerly imported module would not increment these counters, so J08 could remain green while a client receives a message. The notification stub does count pushes, but not destination, and the static scan covers only one service method. **Harm:** customer-directed side effects could escape the claimed J08 proof. **Blocked:** stating that notification, drip, email, and messaging *calls* were observed to be zero across J01–J07. **Minimum fix:** intercept actual outbound methods/transports (or inject throwing/counting stand-ins for each reachable channel) and assert zero client-addressed calls; preserve the single coach-directed `import.complete` exception with recipient and kind asserted on the call itself. This unblocks a discriminating no-client-side-effect proof.
