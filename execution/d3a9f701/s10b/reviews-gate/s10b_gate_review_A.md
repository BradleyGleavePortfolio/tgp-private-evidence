## Blocking finding

**B-1 — pre-existing dangling hook symlinks evade the promised refusal.** The gate refuses `.git/hooks/pre-commit` and `commit-msg` only with `[ ! -e ".git/hooks/$hk" ]` (`gate/s10b-gate-d3a9.sh:178-179`); `-e` is false for a dangling symlink, although that pathname is occupied. The subsequent `lefthook install` may replace it or follow it to an unexpected destination (`:227-246`). **Harm:** a pre-existing hook artifact can be overwritten or installation can affect a path outside the clone, invalidating the claimed no-overwrite gate and possibly losing evidence. **Blocks:** approving this gate for the one-shot relay under the stated hook-safety requirement; it does not establish a product defect. **Minimum fix:** refuse when either `-e` **or** `-L` is true for each hook path (ideally resolve the hook directory using `git rev-parse --git-path hooks`), then re-hash and review the tiny gate delta before relay. The two hook paths were absent at this review, but the source-level guarantee is incomplete.

## Delta review

**Verdict: NO-GO for the gate as revised; binding v1 delta is conditionally GO as source, but no exact candidate is yet filled or proved.** This review covers only `gate/DELTA-review-fix.diff` and `binding/v1/DELTA-review-fix.diff`, not unchanged bytes. The reported S10-A commit `92b9671511279254a8545c4cb531bf965762c597` has parent `e6f20300b495fa9eee9539ae58d30e3b60e5a78c` and tree `b6fbbfd2a6495183433657814193b080c9582ab7` (read-only `git show` in `worktrees/d3a9-s10a`); the new parent pin matches that lineage (`gate/PINS.env:5-10`; `binding/v1/s10b-pg-proof.sh:32-35`). The gate and binding still have `__FILL__` candidate/receipt pins; this is a design decision, not a run or acceptance result.

1. **B-1 substantially closed, with one remaining under-lock directory gap.** The gate now checks the actual hook path with `-e || -L` and requires `.git/hooks` to be a real, non-symlink directory before the lock (`gate/s10b-gate-d3a9.sh:175-181`). It repeats symlink-aware *hook-file* checks under the lock (`:197-201`), so an ordinary dangling `pre-commit`/`commit-msg` symlink is refused before installation. But it does **not** repeat the directory identity check under the lock; replacing `.git/hooks` with a symlink in the prelock-to-lock window could redirect `lefthook install` to an external directory. **Harm:** the no-overwrite/in-clone hook guarantee can fail under concurrent local mutation. **Blocks:** a complete claim that B-1 is closed under the stated pre- and under-lock guarantee. **Minimum fix:** repeat the `git rev-parse --git-path hooks == .git/hooks`, `-d`, `! -L` directory check immediately under the lock before hook installation. This is a race-sensitive source guarantee, not evidence that the current hooks were changed.

2. **B-2 — moved preconditions expose a dangling `STARTED` sentinel bypass.** The gate checks `[ ! -e "$E/STARTED" ]` before prelock and again just before acquiring the lock, but not `! -L` (`gate/s10b-gate-d3a9.sh:116,185-193`). A dangling symlink occupies the sentinel pathname yet passes both checks; `date > "$E/STARTED"` can follow it and write elsewhere. **Harm:** the one-shot grant can be consumed or repeated without a regular sentinel at its expected evidence path, and the write can escape the intended evidence file. **Blocks:** approval of the gate's one-shot/evidence-safety mechanism; this is independent of the fixed hook-file check. **Minimum fix:** refuse `-e || -L` at both checks and, while holding the lock, repeat the occupied-path check immediately before creating `STARTED` (prefer an exclusive regular-file creation to eliminate a race). The proof binding *does* apply `-e || -L` to its sentinel at both prelock checks (`binding/v1/s10b-pg-proof.sh:90-102,192-196`).

3. **No other new A/B finding in the delta.** Prelock refusals now use `prelock.log` and exit without creating `STARTED`/`TERMINAL`; after acquiring the lock, the gate rechecks HEAD/status/index, hooks, node_modules and owned bytes, then retains the original generate/test/commit path (`gate/s10b-gate-d3a9.sh:112-139,184-213`). The binding similarly keeps all committed-blobs/lane/migration/test-count checks before startup, then rechecks fixture SHA, HEAD, clean tree and both critical client-index hashes after lock acquisition (`binding/v1/s10b-pg-proof.sh:96-214`); no check was deleted to create a false pass on stable inputs. Its fixture's symlink-aware data-directory init/destroy change tightens refusal (`binding/v1/s10b-fixture.sh:49-52,94-98`). **C:** the gate README's hook set-aside recipe still uses `-e` alone, so it fails to set aside a dangling symlink that the gate now correctly refuses (`gate/README.md:32-36`); use `-e || -L` and preserve the link itself when documenting the recovery procedure.

**Unblock for a source GO:** close B-1's under-lock directory gap and B-2's `STARTED` symlink bypass, re-hash the scripts, then review those narrow edits. Fill `BASE=92b9671511279254a8545c4cb531bf965762c597`, its tree and migration tree only after the clone is moved to that base, and separately fill binding pins from the actual gate receipt; this static delta review did not run either script.
