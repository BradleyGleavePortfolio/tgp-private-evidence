## 2. Minimal induction/observation contract (proposal, not landed)

* **Induction package:** one unique canonical `sourcePlatform` slug, versioned mapping JSON (source step tokens → supported canonical families, field paths/coercions, explicit shared ID spaces), optional native program/workout rule JSON, and a *declared expected family set* independent of rows actually seen. Pair rules to exactly the mapper's platform and validate both at load; duplicate/conflicting specs fail closed. Reject any family without an authorized native destination rather than inventing a native target (`src/scout/reconstruct/mapping-spec.ts:102-125,328-375,378-429`; `src/scout/reconstruct/native/native-rule-registry.ts:31-50`; `src/scout/reconstruct/families.ts:156-165`).
* **Observation evidence for each run and each declared family (including zero-row families):** tenant/coach + intent + platform/account-scope binding; immutable mapping/observer version and captured-window identity; enumeration scope and exclusions (permissions, date range, inaccessible history); source-issued snapshot/cursor or equivalent reliable bounded-completion proof, page-chain/end-of-list evidence and errors/retries; distinct **source identity set** or tamper-evident digest plus unique count; staging membership/digest and equality/containment proof for *the same* platform/family/id space; a closed, append-only `basis_kind`; timestamp and integrity binding to the settled epoch. A mere `/complete` success claim, number of pages, or equal counts is insufficient (`docs/decisions/2026-09-25-s9-reconciliation.md:186-225`; `src/scout/reconstruct/mapping-spec.ts:109-112`; `src/scout/lifecycle/arbiter.ts:70-87`).
* **Server evaluator:** validate provenance/intent, source-spec match, nonempty and determinable required-family union, artifact freshness and exhaustive successful enumeration, duplicates/collisions and identity-set coverage; return `coverage[f] = {known:true, basis_kind, observed_unique, covers_staged_identities:true}` **only** when evidence proves both source completeness and staged identity coverage. Anything missing, permission-blocked, failed, non-snapshot-inconsistent, or unproven returns `known:false`/`coverage:null`, count `null` if unknown. S9 already reserves this shape; Addendum A says `basis_kind` is on `known:true`, and `observed_unique` is nullable (`docs/decisions/2026-09-25-s9-reconciliation.md:193-225,583-589`; `worktrees/1910a060-s9b/src/scout/reconciliation/coverage.ts:15-50`).
* **Terminal invariant:** the S9 arbiter remains sole terminal writer; `complete` additionally needs stored `success`, no unmapped/no native destination, every staged identity native-verified, all declared relationships closed, and a known basis for *every* required family. Unknown is never represented as zero or accepted by empty-set vacuity; out-of-reach/unsupported becomes explained `partial` or precedence-specific failed/fenced status (`docs/decisions/2026-09-25-s9-reconciliation.md:147-184`; `src/scout/lifecycle/reason-codes.ts:20-32`).
* **Identity/tenant/safety invariant:** wide ledger identity `(coach_id,intent_id,entity_type,source_platform,source_id)` and native provenance keyed by coach/source/family/id; do not merge two source ID spaces without an explicit shared declaration; owner/RLS comparison, no cross-tenant reads or writes (`worktrees/1910a060-s9b/src/scout/reconciliation/facts.service.ts:45-75`; `src/scout/reconstruct/mapping-spec.ts:109-112`). Historical reconstruction is create-only and must never trigger assignments, notifications, email, messages, webhooks, invites, billing or scheduled customer-facing workflows (`docs/decisions/2026-09-24-s8-native-contract.md:104-112,223-242`).
* **Persistence decision is blocking, not optional polishing:** S9 v1 recomputes reports on status reads because `complete` cannot yet occur; its own re-decision trigger is S10, since later deletion could make a stored `complete` contradict the recomputed report (`docs/decisions/2026-09-25-s9-reconciliation.md:329-345`). Prefer a run/epoch-bound immutable observation and settle-time verdict basis plus status semantics distinguishing historic verdict from current native state; table/RLS/retention/erasure need an explicit S10-0 decision rather than an ad-hoc artifact upload.
