# S10-D D1 independent source review — NO-GO

Source-only review of `nest-cli.json` and `scripts/s10-core-diff-gate.sh` against D-S10-1, D-S10-5 and the D-S10-7 S10-D ownership row. I did not run the gate or modify any worktree. The builder's scratch-clone positive/negative results are noted but were not independently reproduced.

## Finding

**A — allowed JSON paths can be symlinks, so the gate can falsely certify mutable or outside-repository induction data.** Check 3 compares only pathnames (`scripts/s10-core-diff-gate.sh:101-118`); `git cat-file -e HEAD:<path>` accepts a symlink blob as “present.” Check 4 excludes all eight allowed pathnames without checking object mode (`:120-128`), and checks 5–7 do not inspect JSON artifacts. A clean D2 commit containing the eight named paths, with one `s10_unseen.json` as a mode-`120000` symlink to an outside JSON file, therefore meets the changed-path set, HEAD-presence and core byte-diff checks; `rg --type ts` does not inspect that JSON. At runtime Node's loader follows a filesystem symlink, so the actual manifest/key or mapping rules can differ from the reviewed Git bytes. **Harm:** “CORE DIFF = 0” could be reported as passing while a mutable external verifier manifest admits an unapproved key, making customer completeness claims trust material not pinned to the allowed commit. **Blocked:** S10-D D1 gate approval and the later D2 source-only attestation. **Minimum fix:** for every allowed path require the HEAD tree entry to be a regular blob of expected mode `100644` (or explicitly approved regular-file mode), rejecting `120000` symlink and `160000` gitlink entries; use `git ls-tree -z` or another NUL-safe tree-mode read, not another `cat-file -e`. Also require the three JSON paths' tracked objects to be regular files at B/HEAD as applicable. **Unblocks:** a gate whose permitted data artifacts are actually commit-pinned files, not references to external content. A scratch-clone negative control replacing one allowed JSON file with a committed symlink should then fail independently.

## Other focused checks

- Checks 1–4 implement ancestor, clean checkout including ordinary untracked files, exact eight-name final diff and byte/mode identity outside the allowed set. The optional HEAD argument is constrained to the checked-out commit. `--no-renames` makes a core rename show up outside the allowed set; a mode-only *core* change is caught by check 4. A pathname containing spaces is quoted through the arrays and pathspecs. A newline-bearing disallowed pathname might confuse check 3's newline/sort comparison, but check 4 uses Git's literal exclusion pathspecs and still rejects the actual outside path; NUL-safe check 3 would nevertheless simplify that argument.
- Checks 5 and 6 accept **only** ripgrep exit 1, rejecting hits and errors; the baseline `src` is read from `git archive`. Check 7 pins the three vocabulary-bearing files and OpenAPI bytes and requires the named symbols at B. The commands capture statuses without unsafe producer-to-`grep -q` pipelines; `set -euo pipefail` does not mask a failed `git diff`, `rg`, `tar` or `git archive`.
- The two added `nest-cli.json` globs are `scout/reconstruct/native/sources/*.json` and `scout/induction/sources/*.json` with `outDir: dist`, matching the native and induction loaders' `join(__dirname, 'sources')` directories after compilation, in the same form as the existing mapping-spec asset entry. The candidate changes only `nest-cli.json` and the D1 gate script, both owned by D-S10-7; no D2 source artifact is added here.

**Disposition:** NO-GO until the allowed-path tree modes are checked and the symlink negative control fails. This is a source-gate defect, not a claim that the current D1 worktree contains a symlink.
