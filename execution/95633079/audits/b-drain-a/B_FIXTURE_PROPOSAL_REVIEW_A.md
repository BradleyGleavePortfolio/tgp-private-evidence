## 2. Findings on the proposal

### FB-0 — required v3 content rule (blocked decision; derives from source F1/F2)
Proposal §6.3 asks to confirm the 21-line identity delta is "the entire product change needed for binding". For *binding* yes; for a **runnable v3** no: v3 must also carry the F1 closure (`down.sql`, `scout-ledger-backfill.ts`, spec stage-3 expectation/`fence()` helper) and the F2 test-side closure, otherwise stage 3 and stage 7 fail on the real fixture regardless of identity. Minimal closure: one v3 tree = v2 + F1 + F2 + identity delta + four additive adapter files; freeze as `frozen-v3/**` with the same BLOBS/diff packet shape; same reviewer re-verifies exactly those lines. Unlocks: phase A gate + the single PG run.

### FB-1 — Class B (binding ordering): §5 pre-steps 1→2 would produce a hookless commit
Proposal §5 orders "1. v3 commit … genuine lefthook hooks" before "2. isolated dependency tree copy". Lefthook, tsc, eslint, prettier and `check-r75` all live in `node_modules`; with no tree in place `lefthook install` cannot run, `.git/hooks` does not exist, and `git commit` would succeed with **no hooks** — violating "no commit before genuine hooks available" and making the commit-time gate evidence false. Minimal closure (prose + one added precondition): reorder to (a) copy + verify the isolated C1 tree (`.package-lock.json 05bc530a…`, `.prisma/client/index.d.ts bf679a16…`), (b) `./node_modules/.bin/lefthook install` and record `.git/hooks/pre-commit`/`commit-msg` presence + sha, (c) phase-A gates, (d) ordinary Bradley-authored commit through those hooks, (e) fill `EXPECT_*` pins from the committed head. Optionally the binding adds a precondition that `.git/hooks/pre-commit` exists and references lefthook. Affected scope: `B_FIXTURE_BINDING_PROPOSAL.md` §5 (and the parent's grant sequence). Unlocks: a truthful committed-head pin.

### FB-2 — Class B (binding bounds): outer bound smaller than the sum of stage bounds
Header/§5 prescribe `timeout -k 30 2400`, but the stage bounds sum to 60+60+180+900+(4×15)+1500+75 = **2835 s**. Neither script traps TERM; `pg_ctl start` detaches the postmaster into its own session. If the outer timeout fires during jest, bash is killed, `fail`/`stop` never runs, the postmaster on 55461 survives, no sentinel and no `RECEIPTS.sha256` are written — the header's "no postmaster survives / every raw exit recorded" would be false. (C1 donor was consistent: 855 s stages vs 900 s outer; B added old-root + bootstrap + a longer jest bound without raising the outer bound.) Minimal closure: outer bound ≥ 3000 s (or lower the jest bound to fit), stated in the header and §5; optional `trap 'fail 124' TERM INT` is acceptable but not required. Scope: `b-pg-proof.sh` comment line 9 + proposal §5. Unlocks: bounded first-failure execution with guaranteed cleanup/receipts.
