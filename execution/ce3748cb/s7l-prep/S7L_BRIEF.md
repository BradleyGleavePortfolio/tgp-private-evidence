## 2. Proposed contract (additive; server owns the run)

**Modes.** `mode ∈ {legacy, server}` on `ScoutImport`. `server` ⇔ `intent_id` is the text form of an owned `ImportIntent.id` and a Start was accepted; `import_intent_id` (UUID, composite FK to `ImportIntent(id, coach_id)`) is set and unique (one run per setup intent; a new attempt needs a new `pair/init`, linking to the old result — PLAN L253). Everything else is `legacy` (CQ-18): existing rows and any client-minted string. Legacy runs are readable as legacy, never promoted (PLAN decision 5).

**Routes (new, `@Roles('coach','owner')`, same dark gate, both phone JWT and extension bearer hit the same arbiter):**
- `POST /api/scout/runs/start {import_intent_id}` → 200 `{intent_id, mode:'server', phase:'discovering', execution_epoch:1, accepted_start_at, deadline_at}`. Preconditions: intent owned by caller (else uniform 404), `paired_at` non-null (409 `intent_not_paired`), `superseded_at` null (409 `intent_superseded`). Duplicate Start on an open run returns the same body (idempotent; race = one row via the `import_intent_id` unique). Start on a terminal run → 409 `run_terminal`. `deadline_at = accepted_start_at + SCOUT_RUN_DEADLINE_MS` (default 300 000, PLAN "five minutes"); both immutable.
- `POST /api/scout/runs/cancel {intent_id}` → 200 `{intent_id, status:'cancelled', execution_epoch}`; idempotent when already cancelled; 409 `run_terminal` when another terminal holds; 409 `legacy_run` for a legacy intent (server owns no run); uniform 404 otherwise. 30/min.
- `GET /api/scout/import/status` (existing path, additive fields, L9): `mode`, `phase|null`, `accepted_start_at|null`, `deadline_at|null`, `last_observed_at|null`, `execution_epoch`, `claimed_status|null` (extension input, `success|partial|failed`), `reason_code|null`, `families[]` (§ L6). `status` enum widened to `running|success|partial|failed|complete|blocked|cancelled|timed_out`; `success` appears only for legacy rows, `complete` only for server rows (the two words are the CQ-18 legacy marker). Old readers see additive fields and new enum members; the only mobile decoder degrades to `unknown` (fact above).

**States and transitions (server mode; every write is CAS on `(coach_id, intent_id, terminal_status IS NULL, execution_epoch = :seen)` under `SELECT … FOR UPDATE`).**
`discovering` (Start) → `transferring` (first ingest or progress) → `reconciling` (`/complete` accepted) → terminal. Terminal ∈ `complete|partial|blocked|failed|cancelled|timed_out`; written once by `arbitrate()` only; `completed_at` set once; `state` mirrors `terminal_status` (legacy column semantics kept). Fences: `cancel` → `fenced_at, fence_reason='cancelled', execution_epoch+1` then arbiter → `cancelled`; deadline is enforced lazily on every mutation and read (`now() > deadline_at` and open → fence `timed_out`, no new timer owner — PLAN decision 6); `revoked` is a reserved `fence_reason` for G3 (L7 seam: S7-L exports `LifecycleService.fence(coachId, intentId, reason)`, adds no route for it).

**Arbiter (L2).** Pure `arbitrate({fence, claim, staged_by_family, ledger_by_family, unmapped_families, reconciliation})` in `src/scout/lifecycle/arbiter.ts`. Precedence: fence `cancelled`/`timed_out`/`revoked` → that outcome; claim `failed` with zero staged rows → `failed` (`transfer_failed`); reconciliation verdict present (S9) → its outcome; otherwise `partial` with `reason_code='reconciliation_not_performed'`. `complete` is emitted only from a reconciliation verdict; S7-L never produces it. The extension claim is stored in `ScoutImportCompletion` unchanged (idempotency anchor kept) and projected as `claimed_status`. `/complete` on a server run: accepted once (phase → `reconciling`, then `onTransferSettled` hook — S7-L default arbitrates immediately; S8-G replaces the hook with reconstruct-then-arbitrate; hook stays CAS-safe), late/duplicate → 200 ack no-op, never overwrites (PLAN L251). Legacy `/complete` path byte-identical to today.

**Fencing (L3).** `assertRunOpen(tx, coachId, intentId)`: inside the writer's transaction, `SELECT execution_epoch, fenced_at, deadline_at FROM "ScoutImport" … FOR SHARE`; open → proceed; fenced/terminal → 409 `run_fenced` (`fence_reason` in body); deadline passed → fence `timed_out` (separate short tx) then 409. Because cancel takes `FOR UPDATE` on the same row, an in-flight ingest/native commit either commits before the fence or observes it — no forever-success race (PLAN L251). Ingest calls it only when the intent resolves to a server run; a UUID intent that is owned but not Started → 409 `run_not_started`; legacy strings skip the gate (old extension builds unchanged: 202/200 as today). `/progress` on a fenced run: 204, ignored, no `last_observed_at` update. S8 native writers must call the same helper (S8-G acceptance).

**Per-family counts (L6).** `families[]: {family, observed_unique: int|null, staged_unique: int, created_native: int|null, already_present_verified: int|null, rejected: int|null, unresolved: int|null, ledger:{reconstructed, skipped, failed}}`. S7-L fills `staged_unique` (distinct `(source_platform, source_id)` per `entity_type`) and `ledger`; native buckets are `null` = "not yet known" (UX rule: unknown is never 0) until S8-B provenance / S9. `observed_unique` stays null until an observation contract exists (S10); extension `final_counts` is a claim, never a bucket. `entity_counts` kept for compat.

**Error codes (fixed catalog, `src/scout/lifecycle/reason-codes.ts`, emitted as OpenAPI enums; CQ-17).** HTTP: `intent_not_paired`, `intent_superseded`, `run_terminal`, `run_not_started`, `run_fenced`, `legacy_run`. Outcome reasons: `reconciliation_not_performed`, `cancelled_by_coach`, `deadline_exceeded`, `transfer_failed`, `unresolved_family`, `revoked` (reserved). No free text is ever returned; the extension's `error_summary` is stored, not projected.

**Invariants.** (1) one terminal write per run, CAS-guarded; (2) `mode='server'` ⇒ `import_intent_id`, `accepted_start_at`, `deadline_at` non-null and `terminal_status ∈` server vocabulary; `mode='legacy'` ⇒ `import_intent_id` null and `terminal_status ∈ {success,partial,failed}` or null; (3) `accepted_start_at`/`deadline_at` never updated after insert (trigger-free: no UPDATE path sets them; asserted by spec); (4) fence ⇒ epoch strictly increases; (5) readers/reconstruct keep gating on `terminal_status IS NOT NULL` unchanged, so cancelled/timed-out runs remain reviewable (CQ-03); (6) `staged === reconstructed + skipped + failed` untouched.

**Compat.** Legacy intents: all existing routes behave byte-identically; rows default `mode='legacy'`. Old extension builds: never call Start, mint non-UUID ids → legacy path. Old backend images under a mixed deploy: an old pod handling `/complete` for a server run would upsert `success` onto a server row and hit the mode CHECK → 500 → extension logs a settlement failure; the run later fences `timed_out` on the new pod. Class C (all scout routes are dark in production); ordering rule recorded: roll the S7-L image fully before any extension build calls Start.
