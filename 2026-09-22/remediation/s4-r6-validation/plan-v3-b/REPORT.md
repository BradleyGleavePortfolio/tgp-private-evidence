## Material finding (Stage 1 grantability on exact bytes)

### V3B-01 — control 2 expects the step's own block to be latched before `SIGNAL_TERM`; bash runs the pending trap first

**Locations:** predicates `75–77`; stub `34–36`; request `65`; lib `85–86,98` and stub `21`. ([predicates](../../../../s4-r6-validation/v3/controls/control-predicates-v3.py), [stub](../../../../s4-r6-validation/v3/controls/s4-r6-control-stub-v3.sh), [request](../../../../s4-r6-validation/v3/SLOT_REQUEST_V3.md), [lib](../../../../s4-r6-validation/v3/runner/s4-r6-lib-v3.sh))

**Mechanism:** at the 4 s deadline `signal_session TERM` (launcher `43`) iterates session members in `pgrep` order — the stub bash (session leader, lowest pid) receives TERM first, then the `timeout` group; `sleep 300` dies, `timeout` exits 143, and the foreground subshell at lib `85` completes. Bash executes a pending trap as soon as the foreground command completes and *before the next command* (`local rc=$?`, lib `86`), restoring `$?` afterwards. Therefore `on_signal` → `block "SIGNAL_TERM" 143` (stub `21`) latches `FIRST_FAIL=SIGNAL_TERM` **before** `block "C-live-step" 143` at lib `98`. The record will show `first_failure.step=SIGNAL_TERM`, `observed_exit=143`, and a *later* `C-live-step` block — the reverse of predicate `75` ("is the live step, not the later SIGNAL block") and of request `65`. Predicates `71,76,77` and the launcher facts (`TIMEOUT`, 124, `timed_out`, `members_at_deadline`≥2, survivors `[]`) would pass; `75` misses → driver `STOP … exit 94` → Stage 1 stops on a correct launcher/lib behaviour.

**Assessment:** this is a wrong *expectation*, not a safety or truth defect — the truthful primary cause of that run is the outer interruption, which is exactly what the record would say. But the packet's own rule (request `72–73, 90`) makes any mismatch a stop → V4, so granting the six controls on these exact bytes cannot yield "all matched" and would consume the grant.

**Smallest closure (predicate/prose only; no launcher/lib/runner/stub-logic change):** predicates `75` → expect `"SIGNAL_TERM"`; `76` → observed `143`; `77` → require a block starting with `C-live-step` *after* the SIGNAL block (or simply "present"); request `65` and stub comment `34–35` reworded accordingly. New predicate hash + manifest; launcher `1113fde0…`, lib `4b357364…`, runner `9ac2195e…` can be carried unchanged. If the builder instead wants the step block to be primary, that is a design change in `on_signal`/`step` and is *not* recommended.

## Non-material observations

- **N-1 bound accounting.** Recorded `worst_case_s = outer+grace+confirm+7` (launcher `75`) and the driver's "reap/publish 7" (`24`) understate the post-exit reap loops (5 s + 3 s, launcher `137–138`) plus publish; request `81` says "≤22 s reap/publish" for validation. Practical effect nil: the driver stops at the first failure, so at most one control reaches its failure worst case; 185 s holds. Optional hardening only: `timeout --foreground --kill-after=10 $((worst+10)) bash "$LAUNCHER"` at driver `39` (foreground mode keeps the launcher a non-leader; TERM routes into its `INTERRUPT` teardown). Not required for grant.
- **N-2 refusal classified by exit code alone.** Launcher `153` maps runner exit 71/73/75 to `RUNNER_REFUSED` even when an `EXIT_RECORD.json` exists (a required step exiting 71/73/75 would be mislabelled a refusal, exit code still truthful). Cheap refinement: additionally require `record_present=false`. No current native consumer documents those exits.
- **N-3 Stage 2 invocation context.** `bash launcher/s4-r6-launch-v3.sh` typed at a job-control shell makes the launcher a group leader → refusal 73 (`86–88`), by design and fail-closed. The grant text should state a non-job-control parent (script, or `bash -c 'bash launcher/…; echo $?'`) and, as request `54` already says, never a non-foreground `timeout` wrapper. Stage 1 is unaffected (driver `39` spawns the launcher as a plain child).
- **N-4 outputs inside the frozen packet directory.** `v3/control-runs/` and `DRIVER-*.log` are created under `v3/` (driver `15,17`); listed hashes stay valid but the frozen tree gains files. Acceptable if recorded; otherwise relocate in a later version.
- **N-5 environment dependencies (fail-closed).** Session census lists zombies until reaped; PID 1 here is `systemd` (reaps orphans), no zombies observed; any lingering zombie would surface as a survivor/quarantine, never as success. `pgrep -s` is procps 4.0.4; `timeout` is uutils 0.8.0 (per-step group, same session) — consistent with the V3 design.
- **N-6 retained from V2 (builder-declared, agreed non-material):** S00 not a bounded step; runner hash recorded not pinned; `99` NOTRUN sentinel; runner has no own deadline; `pgrep -f tgp-…` over-match is fail-closed.
