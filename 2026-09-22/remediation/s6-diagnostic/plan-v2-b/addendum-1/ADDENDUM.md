## A-1 — L82: `reap_group` result is recorded but never gates → MATERIAL false-success record

- **Actual code:** `reap_group "$CUR_PGID" 10 "post:npm-ci"; echo "… cleanup_exit=$?" …; CUR_PID=""; CUR_PGID=""` then L83 `FIRST_EXIT="npm-ci rc=$RC how=$HOW"`, L84 gates **only `$RC`**. Nothing reads `reap_group`'s return again.
- **Path:** `npm ci` exits 0 (L80 `RC=0`) while its owned group still has members after TERM → 10 s → KILL → 1 s (L36 path returns 1, `SURVIVORS=[…] cleanup_exit=1` written). Execution continues through after-checks to L99 `FINAL rc=0 (setup complete …)` and `exit 0`. The EXIT trap then appends `final owned pgid=… members=[…]` (non-empty) *after* the FINAL line.
- **Consequence:** the exit status and the FINAL line — the two things a slot handoff reads — say success while the record itself says an owned group is unresolved. Because fd 9 is inherited by children (my B-04), a non-zombie survivor also **still holds the canonical lock**, so the next owner's `flock -n` fails with rc 75 and the failure is misattributed to "lock busy" rather than to this setup. Realistic occurrence is narrow (only a D-state or un-reaped grandchild can outlive `kill -KILL -- -pgid` inside the same pgid; note `pgrep -g` also lists zombies, so an un-reaped zombie in a no-subreaper sandbox produces `cleanup_exit=1` legitimately as "unresolved"), but the semantics are exactly the "signal only owned resources / preserve cleanup result separately" contract, and a wrong success here hands S2 a busy lock. Material for allocation.
- **Smallest closure (1 line, no new semantics):** capture and gate without merging into first_exit:
  `reap_group "$CUR_PGID" 10 "post:npm-ci"; CLEANUP_EXIT=$?; echo "… cleanup_exit=$CLEANUP_EXIT"; CUR_PID=""; CUR_PGID=""; FIRST_EXIT="npm-ci rc=$RC how=$HOW"; [ "$RC" -eq 0 ] || die npm-ci "$RC" "how=$HOW …"; [ "$CLEANUP_EXIT" -eq 0 ] || die npm-ci-cleanup 7 "cleanup_exit=$CLEANUP_EXIT survivors in owned pgid; lock may be held by survivor; report, do not retry"`.
  `die` already preserves the earlier `FIRST_EXIT` (first writer wins), so first_exit `rc=0 how=exited` stays separate from the cleanup failure; rc 7 is distinct from every npm/step code used. Also include `cleanup_exit=` in the FINAL line text (see A-2 closure) so FINAL is never read alone.

## A-2 — L38 vs L99: ancestor `CHANGED-report` never changes the exit; L99 asserts "ancestor unchanged" unconditionally → MATERIAL false-success record

- **Actual code:** L38 (inside `final_accounting`, run from the EXIT trap and from `on_signal`) computes `ancestor_inventory` after the fact and writes `UNCHANGED` or `CHANGED-report`, no return code, no gate. L99 writes `FINAL rc=0 (… ancestor unchanged — see final_accounting line)` **before** that comparison has run, then `exit 0`. The EXIT trap does not call `exit N`, so the status stays 0.
- **Consequence:** if `/home/user/node_modules` (platform-owned, must-never-change) differs at the end — whether by the install (cwd/`package.json` guards make this unlikely but the guard exists precisely as the fail-closed proof) or by a concurrent platform writer (the inventory is names+mtimes of top-level entries, so any such touch flips it) — the record ends `FINAL rc=0 … ancestor unchanged` followed by `… CHANGED-report`, exit 0. Self-contradictory record with a success exit; the parent's stated acceptance criterion ("ancestor UNCHANGED") is asserted, not checked. Material.
- **Smallest closure:** compute and gate *before* FINAL: after L98 `rec after-checks 0` insert `ANCESTOR_AFTER=$(ancestor_inventory); [ "$ANCESTOR_AFTER" = "$ANCESTOR_BEFORE" ] || die ancestor-changed 8 "before=$ANCESTOR_BEFORE after=$ANCESTOR_AFTER (platform dir differs; report, never remediate)"`, and change L99's text to state only what was gated, e.g. `FINAL rc=0 cleanup_exit=$CLEANUP_EXIT ancestor=UNCHANGED tree=clean strict_resolution=OK`. Keep L38 as the trap-time report (it is also the only accounting on the signal path, where FINAL is already 143).

## A-3 — L80 `wait` after the L79 KILL: does the bounded wait conceal an unresolved owned group? → NOT concealing; one proportionate disclosure

- **Actual code:** L77–79 TERM the group, poll `alive` on the **direct child only** for `INSTALL_GRACE=30`, then `kill -KILL -- -pgid`; L80 `wait "$CUR_PID"` (not time-bounded itself, but for a SIGKILLed direct child it returns promptly with rc 137 unless the child is in uninterruptible sleep, in which case the external `timeout -k 30 1290` TERMs the runner → `on_signal` → `reap_group … 20` → FINAL 143 — still fail-closed). Grandchildren are not waited for at L80; they are handled at L82 by `reap_group` (TERM → 10 s → KILL → 1 s → `SURVIVORS` or `members=none`), and again listed by `final_accounting`.
- **Assessment:** on every KILL path `RC` is non-zero (137/143), so L84 `die` exits non-zero and no false success arises; the owned-group state is not hidden — it is written as `cleanup_exit=` and `final owned pgid=… members=[…]`. What *is* missing is only that the FINAL/die line does not carry the cleanup result (same root as A-1), so a reader of `FINAL rc=137` alone cannot tell whether the group resolved. Proportionate closure: the A-1 `CLEANUP_EXIT` capture plus appending `cleanup_exit=$CLEANUP_EXIT` to the `die` detail on L84. No change to the L78 grace loop or L80 `wait` is needed; making `wait` time-bounded would add complexity without changing any outcome (the external bound already covers the D-state case).
