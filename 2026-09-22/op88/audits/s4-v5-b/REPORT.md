## Material findings (line-bound)

### V5B-01 — MEDIUM (Stage-1 evidence truth; incomplete A-02 "every exit path" closure) / driver — trap-path `finish` scans the PREVIOUS run's session

`LAST_RUN_DIR` is assigned only at driver 137, after `run_bounded` returns. The traps (99-100) call `finish` while `run_bounded` (104-114) is still polling the CURRENT control's launcher; `finish` → `cancel_active` (correct: TERMs `ACTIVE_PID`, waits its worst case) → `session_state "$LAST_RUN_DIR"` (91) → the OWNED_SID of control n−1 (or no scan at all during control 1, leaving `LEASE_FREE=unchecked`). Counterexample: TERM the driver during control 3; the launcher tears down and leaves a recorded quarantine holder (exit 5) or, if defective, releases the lease with leftovers. The receipt line (96) reports `leftovers_initial='' leftovers_final='' quarantine_holder=''` about control 2's dir, and `private_lease_free=false` with no holder (contradictory) or `=true` with unobserved leftovers — the 98 detection (94) is blind on exactly the operator-cancel route the A-02 counterexample named. Ownership itself is not regressed (the launcher owns cleanup and the driver now waits for it), and the next Stage-1 attempt would refuse 95 on a held lease; but the packet's claims "finish() on EVERY exit does cancel → owned-session scan/reap → lease probe" (request 33; map A-02) are untrue for 143/130 during a control. **Smallest correction:** set the current run dir before/inside the poll (e.g. in `run_bounded` after spawn, or in `finish`: `LAST_RUN_DIR=$(ls -1dt "$RECEIPTS"/CONTROL-V5-* 2>/dev/null \| head -1)` when `ACTIVE_PID` is set). ≤3 lines, driver only.

### V5B-02 — MEDIUM (grant-text executability / receipt truth) / driver 158-159 + request §4 line 94 — the success path bypasses `finish`, so the required `EXIT code=0 …` line is never printed

Driver 158 logs `ALL … CONTROLS OK` and 159 `exit 0` directly; `finish` (the only writer of `EXIT code=… leftovers_initial=… private_lease_free=… quarantine_holder=…`, line 96) is not called. Request §4 line 94 defines Pass as "driver 0 AND no MISS AND `EXIT code=0 … leftovers_initial='' private_lease_free=true quarantine_holder=''`": no code path can satisfy the third clause, so a grant evaluator must either fail a genuinely passing run or improvise the criterion (G09 binding lost). The underlying facts do exist per control (line 146/148 require `LEFT_INITIAL=''` and `LEASE_FREE=true` for every launcher control), and the direct-refusal control spawns no session, so this is a truth/criterion defect, not a cleanup gap. The A-02 row (request 33) and map ("driver EXIT line on every exit path") overclaim likewise (70/91/95 also exit without it, pre-spawn — acceptable if worded). **Smallest correction:** replace 159 with `finish 0 "all controls ok"` (adds a final scan/lease probe of the last run and makes §4 literally true; `finish` only escalates to 97/98 on real anomalies), or amend §4 to cite the per-control line-146 facts. ≤2 lines.

Both items change the driver (or the request), so a Stage-1 run on the present `SHA256SUMS` would need repeating; correct first, re-freeze a manifest, then grant once.
