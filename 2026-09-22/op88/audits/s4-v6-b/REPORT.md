## Concrete findings (line-bound)

### V6B-01 — MEDIUM / launcher 107-110, 129-130 with 255 — the `census-members-persist` seam turns stale deadline pids into live signal targets

After the runner has exited, `signal_session` (127-132) censuses via the seamed `census`, whose `MEMBERS` are the pids recorded at the deadline (108: `MEMBERS=${MEMBERS_AT_DEADLINE:-$SID}`), not current session members. Lines 129-130 then run `ps -o pgid= -p <stale pid>` and `kill -TERM -- -<pgid>` / `kill -TERM <pid>` (and again with KILL at 310) roughly 7-12 s after those pids died. The real path's guard against signalling outside the owned session is exactly the `pgrep -s SID` membership that the seam replaces. Counterexample: in `fault-survivors-quarantine` or `fault-receipt-unwritable`, if any of the ~3 dead pids (stub bash, `timeout`, `sleep`) is reallocated to a foreign process within that window, the launcher signals that process's whole group — the record's `signal_route … never outside the session` (189) and the ruling's "no unowned signalling" are then false. Probability: requires the kernel's sequential pid counter to wrap within ~10 s (pid_max 4194304 on a typical host makes this practically impossible; 32768 under heavy forking makes it plausible). Class: the inherited census→kill TOCTOU, widened from milliseconds to seconds, deterministically, twice, in two controls only; the other nine controls and `fault-census-unknown` (MEMBERS="") are unaffected. **Smallest correction (2 lines, launcher only):** in `signal_session`, take the census with faults disarmed (`local f=$FAULT_ARMED; FAULT_ARMED=false; census; …; FAULT_ARMED=$f`) so the injected survivors affect classification (306/313/318) but never the signal target set; the quarantine path and exit codes are unchanged.

### V6B-02 — MEDIUM (A-03 closure completeness; Stage-2 relevant, Stage-1 fail-closed) / launcher 224-239 — lease and standby holder exist before any signal handling

`exec 9>` (224), `flock` (225) and `spawn_holder` (230, up to `QH_VERIFY_S` 5 s) run before `trap 'INTERRUPT=TERM' TERM` (239). A driver cancel or operator TERM/INT landing in that window kills the launcher with default disposition: the launcher's fd 9 closes, but the standby holder (its own session, fd 9 inherited) keeps the lease indefinitely with no `SUPERVISOR_RECORD`, no `OWNED_SID` and — if TERM lands before line 232 — no console line carrying its pid/starttime; identity is then obtainable only through §6's last source (`pgrep -af s4r6-quarantine-holder-<RUN_ID>` + `/proc`). Driver behaviour: `cancel_active` returns at once (launcher dead), `session_state` finds no `OWNED_SID` → NO_SESSION → `finish` code 99 (180) with `private_lease_free=false live_quarantine_holder=''` — fail-closed and truthful about the lease, blind about the holder. Stage 1: harmless to anything outside `control-runs`; next attempt refuses 95. Stage 2: the same window would leave the CANONICAL lock held by an identifiable but unrecorded process — the ruling's "no unrecorded indefinite process". **Smallest correction (≤3 lines):** install the INTERRUPT traps before 224 and, after 235, `[[ -n $INTERRUPT ]] && { release_standby_holder; publish_and_exit INTERRUPTED 143; }` (nothing is owned yet, so release is correct there).
