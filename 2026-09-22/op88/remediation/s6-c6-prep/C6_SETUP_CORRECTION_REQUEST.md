## 3. Concrete risk in the inherited spawn/registration primitive (setup L86–87; same in C6 runner `run_owned` L156–161 and `on_signal` L137; same in S5 setup `74736a58` L91 per the parent)
Pattern: `setsid <cmd> … 9>&- &` ; `CUR_PID=$!` ; `sleep 0.2` ; `CUR_PGID=$(ps -o pgid= "$CUR_PID")` ; fallback `CUR_PGID=$CUR_PID` ; `OWNED_PGIDS+=…`.

- **R1 — child lost on TERM during the window (deterministic, not probabilistic).** bash defers trap handlers until the current foreground command finishes, so a TERM/INT/HUP arriving anywhere from the fork until after `sleep 0.2` runs `on_signal` at a moment when `CUR_PGID` is empty and `OWNED_PGIDS` does not contain the new group. `on_signal` (setup L57: `[ -n "$CUR_PGID" ] && reap_group …`; runner L137 identical guard) therefore reaps nothing; `final_accounting` iterates only `OWNED_PGIDS`, so the survivor census prints nothing and `CLEANUP_FAILURES` stays 0; `FINAL rc=143` is written **while the setsid'd child (its own session, unreachable by `timeout`'s group signal) keeps running**. For the setup that is a live `npm ci` writing `node_modules` after a record that claims no owned members — the "node_modules state undefined" note at L58 is printed, but the census beneath it is false. For the C6 runner it would be an unowned in-band Jest process (lock fd 9 already closed in the child, so the canonical lock is not held by the survivor, but the sandbox CPU and the worktree are).
- **R2 — sampling the caller's PGID.** `ps` at +0.2 s reads whatever group the child is in *at that instant*. Until the exec'd `setsid` binary has actually called `setsid(2)` the child is still in the runner's group (`timeout`'s group, e.g. C5 `4283`). Under load (this sandbox has 2 CPUs and other lanes) 0.2 s is a heuristic, not a barrier. If the stale value is sampled, `OWNED_PGIDS` contains the runner's own group and every later `reap_group` does `kill -TERM -- -<runner pgid>`: the runner terminates itself and `timeout`, the record ends mid-write, and the real child is again unowned. C5 happened to sample correctly in all five steps (`child_pid == child_pgid` in `c5v3.EXIT_RECORD`); that is one observation, not a property.
- **R3 — environmental assumption in the fallback.** util-linux `setsid` 2.41.3 forks only when the caller is already a group leader; a non-interactive bash background job is not, so `$!` is the real child and `CUR_PGID=CUR_PID` is correct **in this shell mode**. Nothing in the script asserts that mode (`set -m` or an interactive launch would silently change `$!` to a short-lived parent and the `wait` rc to 0).

Consequence for this lane: neither the unchanged setup `91fe0f1b` nor the C6 runner (which inherits `run_owned` unchanged from V3.1 by design — see `DIFF_runner_v3.1_to_c6.patch`) may be described as mechanically grantable on the strength of the historical S6 review; both carry R1/R2. The hazard v5 delta and the instrument are independent of this primitive and are unaffected.

## 4. Smallest correction candidate (PROPOSED ONLY — not applied anywhere; one owner for the shared primitive to be named by the parent)
The same eight lines exist in four scripts (S6 setup, S5 setup, S6 V3.1 runner, C6 runner) and in any S5 control driver derived from them. To avoid four divergent fixes, this builder did **not** patch the C6 runner or fork the setup. Proposed shape, for the parent to route to a single owner and to independent review:

1. Register-by-confirmation instead of register-by-timer: after `CUR_PID=$!`, poll (≤ 40 × 50 ms) until `ps -o pgid= "$CUR_PID"` equals `"$CUR_PID"` (child is its own group leader) or the child is gone; only then `OWNED_PGIDS+=`. Never register a value equal to the runner's own `$(ps -o pgid= $$)`.
2. If confirmation fails (timeout of the poll, or sampled pgid == runner pgid): record `SPAWN-GROUP-UNCONFIRMED child_pid=… sampled_pgid=…`, signal **the single pid** (`kill -TERM "$CUR_PID"`, then KILL after grace — never `-$pgid`), `wait` it, count a cleanup failure, `die`.
3. In `on_signal`: if `CUR_PID` is set but `CUR_PGID` is empty, perform the same single-pid TERM/KILL and record it, so the window in R1 is closed rather than narrowed.
4. Optional (parent decision): stamp the shell mode at start (`set -o | grep monitor`) and the actual `timeout`/`setsid` implementations/versions into the provenance file, since R3 and the uutils `timeout` semantics are environmental.

Required with the correction: a **deterministic** negative control for R1 (a hold seam inside the spawn window that a control TERMs, expecting the recorded single-pid reap and nonzero FINAL) and a positive control that the confirmation registers `child_pid == child_pgid`; no probabilistic sleeps as the only race evidence (common contract). Any adopted correction must be re-frozen with new hashes/manifests in each affected packet (for C6: `MANIFEST.c6.sha256` and the packet `MANIFEST.sha256` would be regenerated by this builder on the parent's instruction; the hazard v5 bytes `a91bb732…` and instrument `cf470101…` would not change).
