## Material allocation blockers

### S4-R6-VPA-01 — owned-process census is not a reliable cleanup boundary

**Locations:** shell `57–66,224–238`; pipe helper `100–123,147`; native browser `672–675`. The shell enumerates *present descendants*, including its own command-substitution shell, rather than a stable set of owned jobs; its KILL loop sets `CLEAN_RC=1` even if the enumerated transient PID already exited and `kill` fails. Conversely, children reparented after their parent exits cease to be descendants and are omitted; the later profile-name search cannot cover every npm/Vitest worker or Chrome descendant. ([Shell](../../../s4-r6-validation/runner/s4-r6-validate.sh), [pipe helper](../../../s4-r6-validation/runner/chrome-pipe-discriminator.mjs), [native browser](../../../../worktrees/s4-r6/scripts/browser-load-proof.mjs))

**Counterexample/consequence:** a timed-out command's parent exits while a child survives with a different parent and no proof-profile text; the descendant walk and profile grep no longer establish that child's termination, while its inherited lock descriptor can also outlive the runner. The browser harness kills only its immediate Chrome PID without awaiting exit; the pipe helper can finish its bounded wait with `childExit:null`, remove the profile and still exit 0 on `PIPE_ALIVE`, so the wrapper cannot assume child cleanup was completed. These are static failure paths, not observed leaks in this review. ([Shell, lines 45–50,84,224–238](../../../s4-r6-validation/runner/s4-r6-validate.sh), [browser cleanup](../../../../worktrees/s4-r6/scripts/browser-load-proof.mjs), [pipe cleanup](../../../s4-r6-validation/runner/chrome-pipe-discriminator.mjs))

**Minimal closure:** use the existing isolated-launch boundary with recorded, verified process ownership that survives parent exit; exclude enumeration helpers, handle/reap surviving owned jobs within a bound, and verify absence after KILL before releasing the slot. Do not signal unowned processes; unresolved ownership/termination must remain a failed or quarantined cleanup, not an inferred success. No general runner framework is requested.

### S4-R6-VPA-02 — cleanup/publication failure can still report SUCCESS

**Locations:** shell `225–269`; pipe `125–147`. `RESULT` and the final exit ignore `CLEAN_RC`; with successful steps and no anomalies, even `CLEAN_RC=2` produces `SUCCESS`, a success sentinel and process exit 0. Final worktree state is printed, not enforced, and failure of the Python summary writer does not prevent sentinel publication because its exit is unchecked. ([Shell](../../../s4-r6-validation/runner/s4-r6-validate.sh), [pipe success classification](../../../s4-r6-validation/runner/chrome-pipe-discriminator.mjs))

**Minimal closure:** preserve the first required failure separately, but require verified cleanup, exact clean final source and a successfully written/parsed exit record before any success classification or completion marker; if there is no prior command failure, cleanup/publication failure must give a nonzero overall outcome. Preserve child cleanup uncertainty explicitly rather than treating transport liveness as termination proof.

([Shell](../../../s4-r6-validation/runner/s4-r6-validate.sh), [packager schema, lines 69–89](../../../../worktrees/s4-r6/scripts/package-extension.mjs), [browser inventory and package fields](../../../../worktrees/s4-r6/scripts/browser-load-proof.mjs))

([Selection and binding logic](../../../s4-r6-validation/runner/s4-r6-validate.sh))

**Minimal closure:** require a fresh exclusive run directory and safe run ID; select exactly the newly produced inventory/ZIP pair, enforce actual ZIP hash/entry identity against that inventory and exact HEAD, and require positive/negative browser receipt hashes to name the same original package. ([Shell, lines 118–119,166–180](../../../s4-r6-validation/runner/s4-r6-validate.sh))
