Window ≈ 0.2 s per spawn plus the sub-millisecond gap between `&` and `CUR_PID=$!`. Deterministic when hit; hit only by an external/operator signal in that window.
- R2 (sampling the caller's PGID) — ACCURATE in mechanism; the fallback L160 never rejects a value equal to the runner's own pgid, so a stale sample would later `kill -TERM -- -<runner pgid>` (self-termination, child unowned). C5's five correct samples are one observation, not a property.
- R3 (shell-mode assumption) — ACCURATE and, in my view, the most consequential silent failure: under job control (`set -m`/interactive) the background child is a group leader, `setsid` forks and its parent exits 0, so `$!` refers to an exited pid → `RUN_HOW=exited`, `wait` rc 0 → a hang would be recorded as a clean exit rc 0 with an unowned workload. The frozen C6 launch path (script → `setsid nohup bash -c` → `setsid nohup timeout … bash runner`) is non-interactive without job control, so R3 does not fire there, but nothing asserts it.
- §4 shape sufficiency — SUFFICIENT IN PRINCIPLE for R1/R2 with one addition: (a) register-by-confirmation (`pgid == pid`, never == runner pgid) closes R2 and shrinks R1 to the `&`→`$!` gap; (b) `on_signal` single-pid TERM/KILL when `CUR_PID` set and `CUR_PGID` empty closes the poll window; (c) to close the remaining `&`→`$!` gap, `on_signal` should fall back to `${CUR_PID:-$!}` (bash keeps `$!` of the last background job) — one token, no new abstraction; (d) `wait "$CUR_PID"` after the reap in `on_signal` avoids the zombie false-SURVIVOR noted in Q4. §4 item 4 (stamp `set -o monitor` state and `timeout`/`setsid` versions) converts R3 from assumption to recorded evidence and should be treated as required, not optional.
