## 3. Source delta (`diffs/launcher-v3-to-v31.diff`) — traces

### 3.1 Binding is to this attempt only
- Process chain (unchanged v2/v3 bytes, L229): background subshell `( exec setsid bash -c "$OWN_GATE" … env … timeout -k … bash "$RUNNER" ) &`. With job control off (required by `own_precondition` L66/L148) the subshell is not a group leader, so util-linux `setsid` calls `setsid()` in place: pid stays `$!` = `PID` = `SESSION` (L230) and `own_confirm` L81–87 requires exactly pgid==sid==pid for it. `exec` through gate → `env` → `timeout` keeps that pid; GNU `timeout` forks the workload, which inherits pgid = `SESSION`. The runner's L206 `pgid=$(ps -o pgid= $$ | tr -d ' ')` therefore equals `SESSION`. This is the V3-B smallest-alternative reasoning; it is a platform assumption and P3b is the case that tests it. If it does not hold, (b) fails to bind and v3 behaviour (`unknown` hold) remains — the safe direction.
- Regex L184 anchors `^`, requires the full `YYYY-MM-DDTHH:MM:SSZ` stamp, literal ` START pid=<digits> pgid=<SESSION> ` with a trailing space (so `pgid=12 ` cannot match `SESSION=1`), `head -1`. `SESSION` is numeric (`$!`), so no metacharacter injection into the `sed` expression.
- Stamp normalisation: runner `ts()` = `date -u +%FT%TZ` → strip `-` and `:` → 16-char `YYYYMMDDTHHMMSSZ`, identical shape to `SPAWN_TS` (`date -u +%Y%m%dT%H%M%SZ`, L227). Bash builtin `[ … \< … ]` compares with ASCII ordering; fixed-width digit strings order chronologically. Same host, both `-u`.
- `SPAWN_TS` is taken immediately before `own_spawn_begin` (L227–228); the spawn is after it; hence a legitimate runner START is never earlier than `SPAWN_TS` at second granularity (absent a clock step-back, disclosed).
