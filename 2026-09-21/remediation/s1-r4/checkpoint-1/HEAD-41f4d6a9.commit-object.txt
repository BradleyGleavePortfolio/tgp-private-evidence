S1-DB-01 verifier: treat effective TRUNCATE held by an API role as EXPOSURE (S1-R3-A-01)

Row security governs SELECT/INSERT/UPDATE/DELETE only. TRUNCATE is a separate
table privilege that a FORCE-RLS deny-all table does not defend against, so a
TRUNCATE-only grant (direct or PUBLIC-only) on a server-only relation let the
CRUD-only verifier at b7d7fe59 report protected. verify.sql now includes
TRUNCATE in the has_table_privilege loop for anon/authenticated (effective
semantics: direct, PUBLIC, inherited). No grant, migration or down.sql change;
service_role allowed-path checks unchanged; OK notice unchanged.

full harness section 4b and the standalone narrow entry point

authenticated grant and PUBLIC-only grant on the seeded standalone
"MuxProcessedEvent", each asserted through psql and `prisma db execute`,
each with the frozen b7d7fe59 verifier (extracted from history, sha256-pinned)

role/privilege named, a rollback-only behavioural probe, restore and positive
