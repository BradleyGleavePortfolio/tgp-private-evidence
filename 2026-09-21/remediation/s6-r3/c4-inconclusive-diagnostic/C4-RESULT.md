## Why Jest can print nothing while the loop is alive (read from @jest/core/build/collectHandles.js, jest 29)
A handle is reported only if (a) its own init stack contains `Runtime.requireModule` (module top level) or a jest-circus test/hook frame (`stackIsFromUser`, L109-127), or (b) its `triggerAsyncId` is a *currently tracked* user handle (L179-182). A timer armed from the callback of a previous timer has neither: its stack is only timer internals + the callback, and its trigger (the previous Timeout) is already destroyed and dropped from `activeHandles`. So a self-re-arming timer chain — each hop ≤ a second — keeps Node alive and is invisible to `--detectOpenHandles`. Fixed long timers (5/10-min gc) created inside a test WOULD have been reported; their absence in C4 is consistent with `tmp.clear()`/`queryClient.clear()` having removed those.
