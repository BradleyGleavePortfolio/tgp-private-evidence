## 1. Material finding

### S4-R5-A-01 — MEDIUM / MATERIAL — stale preflight classification can report authentication required after replacement becomes current

**Location:** `background.js:183–205`, called after an asynchronous boundary at `562–565` and `808–811`; the generation-aware check is earlier, at `157–174`. `preflightOwnedSession` reduces the failure to `{replaced: false}`, and `reportPreflightFailure` receives neither the owner generation nor a current-generation check before broadcasting `auth_required`. ([worker source](../../../../worktrees/s4-r5/background.js))

**Exact observed schedule:** start with cold OLD refresh state; accept either `start_import` or `start_ingest`; hold its refresh response; dispatch a replacement whose storage persistence is separately parked; return HTTP 401 for OLD; release replacement persistence after ten or eleven finite microtask turns; let all continuations finish. At notification time the session generation has advanced to B, yet the worker emits `auth_required` and retains `lastError: "login required to import"`; afterwards the replacement acknowledgement is successful, storage contains `NEW_R`, and `request_session_state` reports `hasSession: true`. Both entrypoints exhibit this outcome in the actual imported candidate modules, with synthetic HTTP/Chrome boundaries only. ([boundary probe](preflight-notification-boundary-probe.mjs), [raw results](preflight-notification-boundary-results.json))

The finite probe enumerated 41 release offsets per entrypoint: four of 82 schedules emitted authentication-required while B was current, specifically offsets 10 and 11 for each entrypoint; earlier release controls select the replacement branch, and later offsets report OLD's failure while OLD is still current. Its actual Node exit was **1**, intentionally denoting this observation, with no timeout or thrown harness error; it is not recorded as a passing product test. ([results](preflight-notification-boundary-results.json), [exit receipt](preflight-notification-boundary-exit.json))

**Important temporal limit:** in all four failing schedules, the probe's replacement-acknowledgement continuation had **not** run when `auth_required` was emitted; zero schedules establish a post-acknowledgement notification. This finding is about the already-committed/current replacement and the resulting contradictory terminal state, not a claim that a notification was emitted after the caller observed its acknowledgement. Native Chrome scheduling of this particular microtask interleaving is unverified; the result is an offline source-level interleaving counterexample, not browser proof. ([event-time generation/acknowledgement observations](preflight-notification-boundary-results.json), [replacement commit sequence, session.js:182–192](../../../../worktrees/s4-r5/shared/session.js))

**Consequence:** obsolete failure classification can publish a false authentication requirement while the replacement is locally usable. Neither the replacement token nor its access state was cleared or presented in this schedule, so severity is lower than R4-A-01's demonstrated replacement-bearer requests; nevertheless, the parent's R5 requirement explicitly prohibits obsolete work from falsely reporting that replacement authentication is required. The defect is in final reporting authority, not refresh admission. ([observations](preflight-notification-boundary-results.json), [parent disposition](../../../S4_R4_PARENT_DISPOSITION.md), [broadcast path, background.js:495–500](../../../../worktrees/s4-r5/background.js))

**Closure criteria:** preserve the accepted Start's generation through to the synchronous reporting action and revalidate it immediately before an authentication-required notification; a now-obsolete preflight must report replacement instead, without clearing or presenting B's credentials. Add both-entrypoint late-continuation discriminators, retaining controls where OLD really is still current and cannot refresh, and the existing current-session success/coalescing controls. Reassess the exact successor source and applicable final artifact; do not waive the counterexample merely because the original C1 schedule now passes.

### Source reasoning beyond named fixes

Session admission rejects stale bound callers on entry and under the lock; bound callers for different identities wait rather than share a run, unbound callers can join but retry after an obsolete bound slot stands down, and slot cleanup clears only its own slot (`session.js:214–268`). Rotation changes epoch, not identity; establishment changes identity only after successful persistence, while clear/reestablish is a distinct identity transition. These preserve the same/current/unbound coalescing rules in the examined finite schedules. ([session source](../../../../worktrees/s4-r5/shared/session.js), [mixed controls](independent-followup-results.json))

The session module's in-memory `getAccessToken(expectedGeneration)` fast path deliberately does not enforce ownership itself (`368–376`); current production worker callers use `ownedAccessToken` around it. This is a caller-contract limitation, not an independently reproduced replacement-bearer defect in these consumers. The refresh retry loop awaits settling work rather than spinning, but the comment “bounded” is not proof of a global lifetime bound under indefinite identity churn or permanently pending Chrome storage. ([session](../../../../worktrees/s4-r5/shared/session.js), [worker wrapper](../../../../worktrees/s4-r5/background.js))
