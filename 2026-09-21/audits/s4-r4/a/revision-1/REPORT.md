## 2. New findings

### S4-R4-A-01 — MATERIAL / HIGH — preflight binds Start to the session after the asynchronous work

**Owner:** extension session/worker owner. **Disposition:** OPEN; blocks cumulative authentication/lane clearance. **Affected lines:** `background.js:760–775`, legacy equivalent `511–526`, and admission `1048–1052` / `1068–1072`. The router accepts Start before the preflight await, but the generation is read only after `await getAccessToken()`; its error path is likewise not bound to the original session. ([worker](../../../../worktrees/s4-r4/background.js))

**Reproduction C3, strengthened with an external storage barrier:**

1. Seed only the old refresh token to model an access-token-cold worker; trusted `start_import` returns `{ok:true}` and starts refresh A.
2. The old refresh succeeds; hold its rotation `storage.session.set` while it owns the state lock.
3. Independently dispatch trusted `session_established` B, which queues behind that old commit; then release the old persistence.
4. B establishes before all outer refresh/getAccessToken promises unwind. The original Start gets the old access-token result, passes the string check, but records B's current generation at line 775.
5. The import now obtains **B's bearer** from `ownedAccessToken` and sends `/ingest`, `/progress` and `/ingest/complete` with it, ending `ingest_succeeded`. The identical schedule reproduces on predecessor R3; without replacement both targets correctly use the old minted bearer. ([barrier script](preflight-barrier-probe.mjs), [barrier results including controls](preflight-barrier-results.json))

**Consequence:** local run/account ownership is not fixed at accepted Start. Where B represents another principal, source data from the previously accepted action is offered under that new principal without a new Start; the new generation fences cannot detect it because they were bound too late. The probe demonstrates actual local request credentials and terminal state with synthetic data, **not a live cross-tenant write, proven backend authorization failure, native migration or browser reproduction**. ([request observations](preflight-barrier-results.json), [worker ownership implementation](../../../../worktrees/s4-r4/background.js))

**Related C1 schedule, same missing owned-preflight root:** if B is acknowledged while the old preflight refresh is still on the wire, the old refresh is correctly rejected as stale, but the unowned catch broadcasts `auth_required` and an empty snapshot with “login required to import” although B remains stored and `hasSession:true`. No replacement-token deletion occurs in this schedule. The shipped popup consumes the empty error snapshot; it does not directly route on `auth_required`, so I do **not** claim an observed automatic pairing redirect. ([C1 results](independent-race-results.json), [worker lines 760–775](../../../../worktrees/s4-r4/background.js), [popup lines 115–117, 217–220, 249–252](../../../../worktrees/s4-r4/popup/popup.js))

**Why current tests miss it:** all new worker ownership cases establish an in-memory OLD session and start the import before replacing it at ingest/refresh boundaries; they do not hold the initial token acquisition/rotation persist or replace before the run generation is captured. ([new ownership spec](../../../../worktrees/s4-r4/test/session-ownership.spec.js))

**Closure criteria:** capture/bind the accepted action to its owning session before asynchronous preflight; preserve that identity through token acquisition, success and failure reporting, rather than adopting whichever session exists when the await returns. C1 and the externally-barriered C3 must stop obsolete work truthfully, preserve B, and make no B-authenticated ingest/progress/settlement requests; unchanged-session cold refresh must still succeed. Exercise both entrypoints sharing this preflight pattern. Do not “fix” by prohibiting all new pairing or holding the session lock across network I/O.

### S4-R4-A-02 — MATERIAL / MEDIUM — caller check does not bind queued refresh-token presentation

**Owner:** extension session/worker owner. **Disposition:** OPEN; incomplete credential-ownership boundary, distinct from A-01's late run binding. **Affected lines:** `background.js:240–243`, analogous settlement `334–337`, `ownedAccessToken:154–159` on its cold-refresh path; `shared/session.js:196–219`, request body `237`, commit `277–291`. Generation is checked outside the lock, while refresh admission snapshots a token later without any expected-generation parameter. ([worker](../../../../worktrees/s4-r4/background.js), [session](../../../../worktrees/s4-r4/shared/session.js))

**Reproduction C2:** start a run under OLD, hold its first ingest response, begin B establishment and hold its persistence, then release ingest 401. The outside-lock check still sees OLD, so refresh queues behind B. Release B persistence: that obsolete caller snapshots and presents **`NEW_R`**, commits **`NEW_ROTATED_R`**, and only afterwards notices its run generation is obsolete. It correctly avoids a subsequent new-bearer ingest and destructive cleanup on R4. ([probe schedule](independent-race-probe.mjs), [C2 candidate result](independent-race-results.json))

**Consequence and limits:** the replacement session is still usable in the tested successful-rotation schedule, but an obsolete caller performs a credential presentation and state-changing rotation that the stated ownership boundary prohibits. The post-return fence is too late to prevent consumption of a potentially single-use token; remote reuse/revocation behavior or a lost-rotation-persistence outcome is not measured here. This is materially incomplete token authority, not a claim that C2 alone reproduced cross-account data transfer or logout on R4. ([C2 observations](independent-race-results.json), [declared invariant in worker spec](../../../../worktrees/s4-r4/test/session-ownership.spec.js), [session rotation path](../../../../worktrees/s4-r4/shared/session.js))

**Attribution:** the predecessor also presents `NEW_R`, then retries ingest with the new minted bearer and clears the replacement after its second 401; R4 removes those later harmful actions but not the earlier unowned refresh. This is a remaining cumulative defect, not a claim that R4 introduced all of it. ([paired C2 observations](independent-race-results.json))

**Closure criteria:** preserve the expected session identity into refresh admission/token snapshot and evaluate it under the state lock before presenting the token; ensure a bound caller cannot accidentally join work for a different session. Keep correct unbound/session-current coalescing and do not hold the lock across HTTP. Add pending-establish success/failure, pending-clear/re-establish, rejection/timeout and persistence-failure schedules; assert zero replacement-token presentation from obsolete work, not merely zero replacement-bearer ingest after the refresh. Apply the rule consistently to ingest, initial token acquisition and settlement refresh callers.
