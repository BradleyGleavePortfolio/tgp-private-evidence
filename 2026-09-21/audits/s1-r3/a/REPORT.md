## 4. New material finding

### S1-R3-A-01 — Catalog gate can report protected while an API role holds TRUNCATE

**Classification:** material security-verification defect; medium severity, blocking an unqualified S1 catalog/release-gate attestation. **Owner:** parent-designated S1 fixer only. **Evidence level:** deterministic source counterexample plus PostgreSQL17 documentation; **not database-reproduced by this auditor**.

**Affected lines:** verifier **134–139** checks only SELECT/INSERT/UPDATE/DELETE, while its **22–26**, **48–52**, and **221–222** descriptions imply API privilege removal/protected relations. Forward migration **144** and **200** revoke ALL directly from the two named roles, but the verifier cannot detect later direct TRUNCATE regrant or an effective inherited/PUBLIC TRUNCATE privilege. ([Verifier](../../../../initialization/recovered/s1-r3-b7d7fe5/prisma/migrations/20261224000000_rls_close_public_exposure/verify.sql), [migration](../../../../initialization/recovered/s1-r3-b7d7fe5/prisma/migrations/20261224000000_rls_close_public_exposure/migration.sql))

**Counterexample:** start from the passing synthetic protected state; an authorized synthetic operator grants only `TRUNCATE ON public."MuxProcessedEvent" TO anon`. None of the verifier's tested CRUD permissions, policies, RLS flags, function signatures, paths, or service_role privileges changes, so static evaluation predicts the verifier still succeeds. Yet TRUNCATE is not subject to RLS, including FORCE/deny policies, and requires its own privilege. This is a destructive SQL-role capability, not a claim that PostgREST exposes a TRUNCATE endpoint or that production has the grant. ([Verifier, lines 89–153](../../../../initialization/recovered/s1-r3-b7d7fe5/prisma/migrations/20261224000000_rls_close_public_exposure/verify.sql), [PostgreSQL17 row security](https://www.postgresql.org/docs/17/ddl-rowsecurity.html), [PostgreSQL17 TRUNCATE](https://www.postgresql.org/docs/17/sql-truncate.html))

**Consequence:** a post-restore/post-deploy privilege drift outside CRUD can receive the same green gate intended to prevent API-role access to server-only relations; RLS is not a compensating control for this operation. This does not invalidate the observed direct-CRUD denial matrix or imply the clean candidate directly grants TRUNCATE. ([Verifier, lines 134–139 and 221–222](../../../../initialization/recovered/s1-r3-b7d7fe5/prisma/migrations/20261224000000_rls_close_public_exposure/verify.sql), [PostgreSQL17 row security](https://www.postgresql.org/docs/17/ddl-rowsecurity.html))

**Smallest closure:** add effective TRUNCATE denial to the verifier's exposure checks for both API roles and test it through both supported verifier routes on one seeded standalone target table. Include a PUBLIC-only TRUNCATE grant control to show effective grants are checked; restore state and require the positive verifier again. No blanket grant widening, no migration-policy rewrite, no unrelated full-suite rerun. Parent may first request the small unchanged-head reproduction described in [NARROW_EVIDENCE_REQUEST.md](NARROW_EVIDENCE_REQUEST.md).

## 5. Independent boundary challenges and exact limitations

### Roles, callers, and allow paths

The forward script is tightening-only for the documented 14 server-only relations and current public direct partitions, with explicit deny policies, grant revocation, and no row rewrite/delete. service_role table privileges are preconditions, not repaired by this migration; policy presence is not itself a grant. BYPASSRLS is likewise not table ownership/DDL permission. ([Migration, lines 79–147 and 186–211](../../../../initialization/recovered/s1-r3-b7d7fe5/prisma/migrations/20261224000000_rls_close_public_exposure/migration.sql))

Recorded denied-role behavior uses authenticator→SET ROLE, not HTTP/JWT execution; service_role/postgres allowed operations are representative, not all operations on all 18 relations. The separate non-bypass probe proves default-deny RLS on a populated partition and an insert refusal; it does not isolate the anon/authenticated restrictive policies under restored CRUD grants. Parent-path tests cover coach/member/nonmember reads, member insert, and forged sender, not a full DM/update/delete/cross-workspace API matrix. ([Harness, lines 251–291](../../../../initialization/recovered/s1-r3-b7d7fe5/test/db/s1-rls-close-public-exposure.sh))

PrismaService does not select a role explicitly, and schema `DATABASE_URL` differs from migration `DIRECT_URL`; the interceptor sets transaction-local GUCs rather than SET ROLE and does not wrap business queries in the same transaction. These facts support retaining the live-app-client requirement, not asserting the interceptor as a demonstrated tenant boundary. No partition-helper caller was found in the inspected backend `src`, `scripts`, or `.github` paths; that says nothing about external scheduled jobs. ([PrismaService](../../../../initialization/recovered/s1-r3-b7d7fe5/src/prisma.service.ts), [schema, lines 8–18](../../../../initialization/recovered/s1-r3-b7d7fe5/prisma/schema.prisma), [interceptor, lines 21–57](../../../../initialization/recovered/s1-r3-b7d7fe5/src/common/interceptors/rls-context.interceptor.ts), [runtime packet](../../../../repos/tgp-private-evidence/2026-09-20/remediation/s1-r2/revision-1/RUNTIME_ROLE_VERIFICATION_PACKET.md))

### Partitions and future objects — retained S1-A-07 limit

The helper protects a public immediate child within the same function call and refuses unrelated/non-public relations; its EXECUTE grant to service_role does not confer the required ownership. No event trigger or global default-privilege repair is installed, so arbitrary future manual tables/partitions and subpartition descendants are not automatically covered. ([Migration, lines 162–256](../../../../initialization/recovered/s1-r3-b7d7fe5/prisma/migrations/20261224000000_rls_close_public_exposure/migration.sql))

**Additional static observation, not a new demonstrated deployment regression:** verifier **74–77** discards each child's namespace/OID and later resolves `public.<name>`; **154–155** only requires one attached child. Its “every partition is still attached” comment must not be promoted into evidence of that property. The forward protector instead rejects a non-public child; verifier and migrator do not have equivalent future-object acceptance domains. ([Verifier, lines 73–90 and 143–155](../../../../initialization/recovered/s1-r3-b7d7fe5/prisma/migrations/20261224000000_rls_close_public_exposure/verify.sql), [protector, lines 178–185](../../../../initialization/recovered/s1-r3-b7d7fe5/prisma/migrations/20261224000000_rls_close_public_exposure/migration.sql))
