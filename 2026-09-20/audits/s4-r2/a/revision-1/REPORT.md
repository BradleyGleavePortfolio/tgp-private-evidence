## 4. New findings

### S4-R2-A-01 — MATERIAL: authentication body reads have no deadline; stalled refresh remains coalesced

**Boundary:** cumulative S4 final-candidate acceptance / unconditional shipping-merge attestation and release; **owner:** extension session/pairing owner. **Attribution:** reproduced at both main/base and candidate; not introduced by R2. ([candidate proof](auth-body-probe.json), [baseline proof](auth-body-baseline-probe.json))

`shared/pairing.js:62–82` and `shared/session.js:152–169` await `fetchWithTimeout` only until headers, then call `res.json()` outside its deadline; `shared/net.js:17–58` clears the timer when the default response consumer returns. The replay-source and ingest-ACK paths already use the consumer correctly, but authentication does not. ([pairing](../../../../worktrees/s4/shared/pairing.js), [session](../../../../worktrees/s4/shared/session.js), [net](../../../../worktrees/s4/shared/net.js), [background](../../../../worktrees/s4/background.js))

My probe supplies an actual streamed Response whose JSON prefix arrives but stream never closes: both 15000-ms deadline handles are cleared, no live timeout remains, and pairing/refresh stay pending; after local clear and re-establish, another `refreshAccessToken()` still joins the old pending refresh, with only one refresh fetch recorded. ([executable probe](auth-body-probe.mjs), [measured result](auth-body-probe.json))

**Actual consequence:** an ordinary partial HTTP response can leave the sole pairing submit disabled without its timeout remedy, or stall a cold-worker/mid-run token refresh and all coalesced callers until browser/runtime/network teardown; local token epoch guards prevent stale commit but do not release this wait. This is a live auth/recovery path, not a dormant permission or cosmetic issue. ([pair UI](../../../../worktrees/s4/popup/pair.js), [session coalescer](../../../../worktrees/s4/shared/session.js), [candidate proof](auth-body-probe.json))

**Smallest closure:** move authentication response consumption inside the existing finite-deadline consumer, retain sanitized error categories and epoch fencing, bound token-response size, and add headers-success/body-stall tests for pairing and refresh plus fresh-refresh-after-timeout/clear/re-establish recovery; preserve tests for malformed body and stale rotation. The current tests cover fetch-not-resolving and malformed-body rejection, not this partial-response wait. ([pairing tests](../../../../worktrees/s4/test/pairing.spec.js), [refresh tests](../../../../worktrees/s4/test/session-refresh-path.spec.js), [net helper](../../../../worktrees/s4/shared/net.js))

No Bradley decision is needed for this ordinary remediation; the parent must not modify the frozen candidate underneath either auditor, and a changed artifact requires scoped re-attestation. ([brief](../../../R2_AUDIT_BRIEF.md), [EXECUTE](../../../doctrine/EXECUTE.txt), [G09–G11](../../../../repos/context/AGENT_RULES.md))

### S4-R2-A-02 — residual diagnostic leak in dormant legacy entrypoint

**Boundary:** nonblocking for the presently shipped popup path, but blocks any claim of universal persisted-error redaction and must be removed/fixed before legacy entrypoint activation; **owner:** extension worker/extractor owner. ([router](../../../../worktrees/s4/background.js), [shipping inventory](../../../../repos/evidence/2026-09-20/remediation/s4-r2/revision-1/artifacts/tgp-importer-extension-0.3.0-rc.1.c5a5ae1.inventory.json), [popup producer](../../../../worktrees/s4/popup/popup.js))
