## 5. New findings

### S1-R2-A-01 — Destructive proof harness has no enforceable disposable-target boundary

**Classification:** material safety defect in newly committed test tooling; blocks merging/running this complete package as delivered. **Owner:** S1. Not a forward-DDL privilege escalation or evidence that any real database was damaged.

The header promises “ONLY” a disposable local PG17 cluster, but the only URL check is “environment variable is present.” The first database operation, before any version/role/host/name/confirmation check, sends `DROP DATABASE IF EXISTS $DB WITH (FORCE)`, another drop for `${DB}_lock`, and `CREATE DATABASE $DB` to the caller-supplied URL. The DB argument is interpolated as SQL without identifier validation. ([Harness, lines 5–6, 22–29 and 51–53](../../../../worktrees/s1/test/db/s1-rls-close-public-exposure.sh), [static extraction](static-proof-limits.json))

**Counterexample from source:** supply a reachable non-disposable cluster's administrative URL and the name of an existing non-current database as the first argument; line 52 attempts to terminate sessions and drop that database. Even a loopback URL can refer to a tunnel or an unrelated local database. The later synthetic-password failure cannot undo the earlier drop. No malicious untrusted caller is required: this is an operator-targeting mistake at a privileged destructive boundary. I did not execute this counterexample.

**Minimal correction:** before any destructive call, validate a literal permitted loopback endpoint/dedicated port, reject URI query/host overrides, validate/restrict database names to a disposable namespace, and require explicit disposable-cluster confirmation. Use proper SQL identifier handling. Fail closed on mismatched server identity/role flags and expected version; do not rely on IF-NOT-EXISTS role creation to establish fidelity. These controls need small negative tests that prove no `psql` action is reached for a rejected target. ([Current missing checks and destructive call](static-proof-limits.json), [bootstrap preserves preexisting roles](../../../../worktrees/s1/test/db/_support/supabase-like-bootstrap.sql))

**Closure evidence:** guarded final-head harness plus command-stub negative tests for remote endpoint, wrong endpoint/port, arbitrary existing DB name and SQL metacharacters; safe synthetic-path proof remains attributable. Parent should not run the unsafe harness against any production-like credentials to reproduce this.

### S1-R2-A-02 — Recovery packet calls non-discriminating tests proof of whole-file atomicity and timeout cleanup

**Classification:** material evidence/truthfulness gap in the recovery attestation; not a demonstrated DDL atomicity failure. Blocks an unqualified T4 recovery attestation/atomicity-dependent application until a bounded test or explicitly narrower recovery claim closes it. **Owner:** S1, parent schedules execution.

The lock is held on DunningAttempt, which is altered inside the first 14-table DO. All earlier table ALTERs are inside that same DO statement. PostgreSQL statement-level rollback alone would leave every tested table's RLS flag unchanged even if the client did not execute the complete multi-statement file atomically. Thus “failed Prisma attempt is ATOMIC” does not experimentally prove the whole-file property asserted in the migration comments and packet. ([Harness, lines 103–117](../../../../worktrees/s1/test/db/s1-rls-close-public-exposure.sh), [migration, lines 44–57 and 74–129](../../../../worktrees/s1/prisma/migrations/20261224000000_rls_close_public_exposure/migration.sql), [packet](../../../../repos/evidence/2026-09-20/remediation/s1-r2/revision-1/REPORT.md))

Likewise, both leakage assertions use `q()`, which starts a new psql connection; the historical buggy script with persistent session SETs would also show defaults in that fresh connection. RESET is present and correct by inspection, but those PASS lines cannot be its regression proof. ([Harness, lines 37, 118 and 139](../../../../worktrees/s1/test/db/s1-rls-close-public-exposure.sh), [final PASS labels](../../../../repos/evidence/2026-09-20/remediation/s1-r2/revision-1/proof-run-05-head-90a6647.log))

**Consequence:** an operator could infer that a late helper/partition failure cannot leave earlier changes applied, or that a future regression cannot leak timeout settings to later migrations, when neither behavior was discriminated by the retained test. This does not imply row loss: the source remains idempotent and the observed failed-attempt recovery is useful. It requires one better-placed lock and one same-connection check, not a full-suite rerun. ([Idempotent recovery contract](../../../../worktrees/s1/prisma/migrations/20261224000000_rls_close_public_exposure/migration.sql))

**Minimal closure:** block an existing partition in a separate synthetic session so failure occurs after the first DO, run the real Prisma path, then verify the first DO's effects and helper catalog changes rolled back. In the same connection that runs the SQL, inspect timeout settings after completion. Retain the failed-history/resolve/deploy evidence. Alternatively explicitly narrow claims and prove the recovery from an intentionally partial late-stage state; do not retain an unearned all-or-nothing assertion. The exact bounded request is saved separately and has **not** been executed by this auditor. ([Parent execution request](BOUNDED_EXECUTION_REQUEST.md))
