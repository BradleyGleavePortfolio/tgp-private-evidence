### NEW pre-existing findings surfaced by validation (not introduced by S6; outside S6 lane — for parent routing)

**S6-R2-NEW-1 — Release bundling of unmodified `main` fails: `Unable to resolve module react-native-mmkv` (MATERIAL, release-blocking, baseline).**
`src/storage/mmkv.ts` does `require('react-native-mmkv')` inside try/catch as an optional native probe; the package is undeclared and absent (the declared-dependency guard allow-lists it on the belief that "the probe always throws and every build takes the AsyncStorage fallback"). Metro resolves statically, so `expo export --platform android` fails at bundle time. Proven on **unmodified main `a5933fd6`** (`git archive` copy with `node_modules` symlinked, cold cache, no stub): exit 1, `logs/09-baseline-main-a5933fd6-expo-export.log`; and on the S6 head without stub: `logs/06a-expo-export-FAILED-unresolved-mmkv.log`. Unknown whether EAS builds hit the same path (they run the same Metro bundling; if a prior EAS build succeeded, something in that environment differs — UNKNOWN, not inferred). **Not fixed here**: the smallest fixes all touch the storage/native boundary (make the probe bundle-safe via a Metro `empty` resolution plus a real export check in `isMmkvAvailable()`, or declare the package and link a native module) — a separate decision per the guard's own comment and the parent's "do not weaken native boundary". Held as an actual release-export gap.
